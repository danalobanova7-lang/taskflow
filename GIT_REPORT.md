## Модель ветвления — Git Flow

- `main` — боевая версия.
- `develop` — сборка следующего релиза.
- `feature/*` — одна задача, вливается в `develop`.
- `release/*` — подготовка релиза.
- `hotfix/*` — срочный фикс прода.

## Чему научилась

- Работать с тремя зонами Git: рабочая директория → staging → репозиторий.
- Писать осмысленные сообщения коммитов (`docs:`, `feat:`, `fix:`).
- Создавать ветки и переключаться между ними.
- Открывать Pull Request в правильную ветку (`develop`, не `main`).
- Не коммитить секреты (`.env` — в `.gitignore`).
